# plan-rosta — приложение Юли

Личное веб-приложение: программа тренировок, питание, дыхание, замеры, цикл и
дневники. Работает на GitHub Pages, ставится на телефон как PWA.

**Живёт по адресу:** https://jgoleva-glitch.github.io/plan-rosta/
**Второй репозиторий:** `../Тед Лассо` — там бот и источник всех справочников.
Прочитай и его `CLAUDE.md`: половина правил про эту папку живёт там.

Общение с Юлей — по-русски, комментарии в коде тоже. Правила работы с ней — в
`~/.claude/CLAUDE.md`: объяснять перед действием, ждать «ок», ошибки
пересказывать человеческим языком.

---

## Главное правило: сюда идёт основная работа

Юля сказала прямо: «мне главное приложение, можно не тратиться сильно на бота».
Приложением она пользуется каждый день с телефона и ставит отметки здесь.

Отсюда два следствия:

1. **Приложение — источник истины.** Расходятся приложение и бот, правим так,
   чтобы совпало с приложением, и дублируем логику в боте, а не наоборот.
2. **Новое делается сначала и полностью здесь**, до рабочего состояния. В бота
   переносится только то, что даёт что-то сверх приложения: напоминание в нужный
   момент, отметка одним касанием в телеграме. Задача вида «добавь в приложение
   и бот» означает, что основное время уходит сюда, а бот получает минимальную
   рабочую версию.

Цикл, замеры и отметки Юля ставит здесь; бот читает их через облако.

### `data/` — генерируемая папка

Шесть файлов (`workouts`, `exercises`, `menu`, `breathing`, `shopping`, `cycle`)
собираются скриптом из бота:

```bash
cd "../Тед Лассо/bot" && ./venv/bin/python tools/export_to_app.py
```

Источник — `../Тед Лассо/bot/data/`. Правки вносятся **туда**, потом запускается
экспорт. Если поправить `plan-rosta/data/` напрямую, следующий экспорт всё
затрёт, а бот и приложение разъедутся.

Экспорт попутно убирает личную привязку диагнозов: правила безопасности
остаются, но формулируются как свод правил, а не «у тебя грыжа». В конце он сам
проверяет, что личных упоминаний не осталось.

## Устройство `index.html`

Один файл выбран сознательно: GitHub Pages без сборки, править можно с любого
устройства, нет шага компиляции, который может отвалиться.

### Пять отдельных блоков `<script>`

Это **самая частая ловушка**. Блоки — независимые IIFE, общей области видимости
у них нет:

| Блок | Что внутри |
|---|---|
| 1 | Трекер-дневник (КПТ, заземление, работа), навигация, анимация появления |
| 2 | **Тело:** тренировки, дыхание, питание, замеры, цикл, счётчики |
| 3 | Синхронизация между устройствами |
| 4 | Дневник настроения и цикла |
| 5 | Натальная карта (только localStorage) |

Константа из блока 1 в блоке 2 **не видна**. Уже наступали: `MONTHS` объявлена в
блоке 1, в блоке 2 понадобились месяцы — пришлось завести свой `MON_SHORT`.
Прежде чем использовать переменную, проверь, в каком блоке она объявлена.

### Расписание тренировок

```js
var DAY_PROGRAM = {1:'D', 2:'L1', 3:'L2', 4:'A', 5:'B', 6:'C', 0:'L3'};
var HEAVY_DAYS  = {A:1, B:1, C:1, D:1};
```

Воскресенье = 0 (`getDay()`). **Тренировка есть каждый день, выходных в
расписании нет намеренно.** Четыре ударных дня (A, B, C, D) и три лёгких
(L1–L3). Какие дни делать — решает Юля; отдых это день без галочек, он просто не
попадёт в счётчик. Не возвращай понятие «выходного дня»: это её прямое решение.

У бота то же расписание в `../Тед Лассо/bot/config.py` — `DAY_PROGRAM` и
`HEAVY_DAYS`. **Меняешь в одном месте — меняй в обоих.**

### Неделя программы считается от понедельника

```js
function weekAnchor(){ /* понедельник той недели, в которую пришёлся старт */ }
```

Не от даты старта. Иначе при старте не с понедельника номер недели
переключается посреди недели: понедельник остаётся в прошлой, а среда с
пятницей уходят в следующую — и фаза с меню рвутся внутри тройки тренировок.
Та же логика в `bot/content.py::week_number`.

## localStorage: что где хранится

Всё личное живёт только на устройстве. В репозитории личных данных нет.

| Ключ | Содержимое |
|---|---|
| `tl_start` | Дата начала программы (ISO) |
| `tl_place` | `gym` или `home` |
| `tl_periods` | Массив дат месячных |
| `tl_measures` | Замеры: одна запись на дату |
| `tl_weights` | Рабочие веса: `{упражнение: {value, date}}` |
| `tl_done_ГГГГ-ММ-ДД` | Отметки упражнений за день |
| `tl_total_ГГГГ-ММ-ДД` | Сколько упражнений было в тот день |
| `tl_shop_*` | Отметки в списке покупок |
| `tl_mood` | Дневник настроения и приём препарата: одна запись на дату |
| `tl_natal_chart`, `tl_birth` | Карта и данные рождения — **только здесь** |
| `tlts_<ключ>` | Метка времени изменения, для синхронизации |

### Почему `tl_total_` существует отдельно

Счётчику закрытых дней нужно знать, закрыт день или брошен на середине. Для
этого нужно и число отметок, и сколько упражнений в этом дне было — второе
нигде больше не хранится, программы у дней разной длины. День засчитывается при
**60 %** отмеченных: добить последнюю растяжку из девятнадцати — не повод
обнулять всю тренировку.

Пишется при отметке галочки — с числом упражнений того дня, который реально
делали, а не того, что стоял в расписании.

### Отметки упражнений обязаны быть с префиксом дня

Номера упражнений порядковые: `w0`, `m0`, `c0`. Во всех днях они одинаковые,
поэтому к ним добавляется ключ дня: `A:m0`, `L2:w3`. **Без префикса отметки дня
A проявятся в дне B** — третье упражнение везде `m2`. Уже ловили.

Отметки любого дня пишутся на **сегодняшнюю** дату: Юля может сделать не тот
день, что в расписании, и это должно зачесться.

## Синхронизация между телефоном и компьютером

Через личный Cloudflare Worker. Код воркера Юля копирует из самого приложения
(раздел 14) — он там лежит текстом, чтобы не искать по репозиториям.

- `tlCollectData()` собирает **всё с префиксом `tl_`** и отдаёт с метками времени
- `tlApplyData()` вливает чужое: новее по `tlts_` — побеждает
- Заголовок `X-Sync-Secret`, эндпоинты `/save` и `/load`

Из этого следует: **любой новый ключ с префиксом `tl_` синхронизируется сам** —
ничего дописывать не надо. Обратная сторона: мусорные `tl_` ключи попадут в
обмен, так что не заводи их для одноразовых вещей.

Списки **сливаются, а не перетираются** — иначе отметка с телефона стёрла бы
отметку с компьютера: `tl_done_*`, `tl_shop_*`, `tl_periods`. По одной записи на
дату, свежая заменяет старую: `tl_measures`, `tl_mood`. Всё остальное — по
метке времени. Добавляешь ключ со структурой — реши, в какую из трёх групп он
попадает, и допиши в `tlApplyData`.

Бот читает те же данные через `bot/cloud.py`. Чтобы это заработало, Юля
нажимает «Связать с ботом» в приложении и отправляет боту `/sync_key`.

## Как проверять изменения

Не открывай `index.html` файлом: `fetch` для `data/*.json` не сработает.

```bash
cd "/Users/ulia/Claude AI/plan-rosta" && python3 -m http.server 8899 --bind 127.0.0.1
```

### Кэш придётся сбрасывать руками

Обжигались дважды: страница подтягивает старый `data/workouts.json` из
HTTP-кэша, отрисовка падает на `plan.title`, а в блоке остаётся содержимое
прошлого дня — выглядит как «переключатель не работает».

```js
const regs = await navigator.serviceWorker.getRegistrations();
for (const r of regs) await r.unregister();
for (const k of await caches.keys()) await caches.delete(k);
for (const f of ['workouts','exercises','menu','breathing','shopping','cycle'])
  await fetch('data/' + f + '.json', { cache: 'reload' });
location.reload();
```

**При каждом выпуске поднимай `CACHE_NAME` в `sw.js`** (`plan-rosta-v4` → `v5`),
иначе у Юли на телефоне останется старая версия и она скажет «не обновилось».

### Скриншоты часто приходят пустыми

Если панель браузера скрыта, `computer screenshot` отдаёт белый кадр, хотя
страница жива. Проверяй через DOM — `read_page`, `get_page_text` или `javascript_tool`:
это и надёжнее, и позволяет сверить числа, а не только увидеть картинку.
Верстку на узком экране смотри через `resize_window` с пресетом `mobile`.

## Грабли, на которых уже стояли

**Даты.** `new Date('2026-08-02')` разбирается как UTC-полночь и на московском
времени уезжает на день назад. Из-за этого не работала кнопка «Отметить» в
цикле. Только `parseISO()`.

**Анимация появления.** Порог в 12 % высоты недостижим для длинных разделов —
они никогда не «появлялись». Свой IntersectionObserver с порогом 0.

**Переносы в карточках.** `white-space: nowrap` на `:last-child` задевал строки
из одного элемента, и текст уезжал за край. Нужен `:not(:first-child)`.

**Меню-бургер на телефоне.** Без `max-height` и `overscroll-behavior: contain`
не прокручивается, часть пунктов недоступна.

**Поля веса.** Показываются только там, где вес бывает — основная часть ударного
дня. Guard `needsWeight`; на лёгких днях вес у упражнений вообще не задан, иначе
к каждой растяжке дописывалось «· Без веса». Вес выводится сразу после подходов:
если поставить его после длинной подсказки, его не видно.

**Плашка дня цикла — только на сегодняшнем дне.** Она считается от сегодняшней
даты, и на дне A, открытом заранее, показывала бы неверный номер.

**Таймер отдыха** прячется на лёгких днях: там нет подходов.

## Дневник настроения (раздел 13)

Сделан под вопрос «это ПМДР или общий фон». Десять симптомов по шкале 1–5,
вечером около минуты. Раздел сам сравнивает два окна:

- **предменструальное** — 5 дней перед фактической отметкой месячных, считается
  назад от реальной даты, поэтому нерегулярный цикл не мешает
- **чистое** — 6–12-й день цикла: месячные закончились, до лютеиновой фазы далеко

Окна не пересекаются: 1–5 месячные, 6–12 чистое, последние 5 предменструальные.
Разница ≥ 30 % подсвечивается как заметный паттерн. Есть кнопка «Скопировать
сводку для врача».

### Отметка таблетки

Строка «Таблетка» стоит **первой**, до дневника, и сохраняется **одним
касанием** — без кнопки «Сохранить». Это не небрежность: лишний шаг «не забудь
нажать сохранить» даёт дыры в истории приёма, а именно она и нужна врачу.
Повторное нажатие снимает отметку.

Хранится в поле `pill` той же записи: `'y'` принято, `'n'` пропуск, нет поля —
не отмечено. Отсюда два следствия, которые легко сломать:

- **Запись может существовать без дневника** — когда отмечена только таблетка.
  Такие дни исключаются из средних по фазам и из графика через `hasMood()`,
  иначе день с одной отметкой засчитается как день с нулевыми симптомами и
  занизит среднее. В истории у него стоит прочерк, а не ноль.
- **Если не осталось ничего** — ни оценок, ни отметки, ни заметок — запись
  удаляется целиком. Без этого повторное нажатие по кнопке не снимало бы
  отметку: сохранение выходило раньше и старое значение оставалось.

Бот умеет то же самое: `/pill` и напоминание в 8:30 пишут в этот же ключ через
облако. Формулировки про пропуск — без упрёка, у Юли РПП. Дозировок ни бот, ни
приложение не советуют.

Тонкости, которые легко сломать:

- **День цикла не хранится в записи.** Считается из отметок месячных, поэтому
  поправленная задним числом дата пересчитывает всю историю сразу.
- `moodCycleDay()` живёт отдельно от штатного `cycleDay()`. Штатный считает от
  последней отметки и для всего, что раньше неё, отдаёт `null`, а дневнику нужна
  вся история, чтобы сравнивать циклы между собой.
- Раздел поднимается **до** загрузки справочников: запись можно сделать, даже
  когда `data/*.json` не подъехали.
- `DOSE_START` и `DOSE_PLAN` — только подсказка в поле дозы. Поле редактируемое:
  поменяет врач схему — Юля впишет своё, история не пострадает.

## Приватность — не косметика

Натальная карта и данные рождения **никогда** не попадают в код или репозиторий,
только в localStorage этого устройства. Историю git уже переписывали (orphan
branch + force push), когда они там оказались. Не возвращай их в файлы ни в
каком виде, включая примеры и тесты.

Медицинские документы (`*.pdf`, `*.docx`) в `../Тед Лассо` лежат локально и
закрыты в `.gitignore`. Репозиторий публичный — GitHub Pages.
